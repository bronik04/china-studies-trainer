# Выкладка на GitHub Pages — план реализации

> **Исполнителю-агенту:** ОБЯЗАТЕЛЬНЫЙ ПОДНАВЫК — `superpowers:executing-plans`
> (`superpowers:subagent-driven-development` только после явного разрешения
> владельца продукта: `AGENTS.md`, «Ветвление и ревью»). Шаги размечены
> флажками `- [ ]`.

**Цель:** приложение открывается по адресу
`https://bronik04.github.io/china-studies-trainer/` и обновляется само при
слиянии в `master`.

**Замысел:** базовый путь задаётся в `vite.config.ts` один раз и попадает во
всё, что собирает Vite; два ручных адреса снимков сводятся в один модуль,
который узнаёт базовый путь через `import.meta.env.BASE_URL`. Выкладку делает
вторая работа в существующем `checks.yml` — она забирает уже проверенную сборку
артефактом и потому не может выложить непроверенное.

**Технологии:** Vite 8, GitHub Actions, GitHub Pages (источник — GitHub
Actions, не ветка).

**Спецификация:** `docs/superpowers/specs/2026-09-15-github-pages-design.md`

## Общие ограничения

- Ветка работы — `feat/gh-pages`, создана от `master`. В `master` напрямую не
  писать (`AGENTS.md`).
- Адрес сайта: `https://bronik04.github.io/china-studies-trainer/`. Базовый
  путь: `/china-studies-trainer/` — с ведущей и завершающей косой чертой.
- Действия GitHub закрепляются по sha коммита, версия — комментарием рядом.
  Правило действует в `checks.yml` и не меняется.
- Интерфейс, задания и сообщения об ошибках — по-русски (`AGENTS.md`).
  Комментарии и тексты в коде — тоже по-русски, как во всём проекте.
- Готовность изменения: линтер, тесты, сборка зелёные; основной сценарий
  проверен вручную; `CHANGELOG.md` обновлён (`AGENTS.md`).

- [ ] **Шаг 3: свести адрес в одну строку и добавить набор**

```ts
/**
 * Адрес одного файла снимка. Ниже нет ни одного другого места, где имя файла
 * собирается по частям: базовый путь сайта живёт здесь и больше нигде.
 */
function photoFile(photoId: string, width: number): string {
  return `/photos/${photoId}-${width}.webp`;
}

/**
 * Адрес файла, который браузер и покажет: самый широкий из тех, что есть.
 *
 * Отдельным модулем, а не рядом с `CollectionImage`: тот файл отдаёт
 * компонент, и посторонний экспорт рядом с ним ломает обновление на лету.
 *
 * Нужен раунду «Культура»: он обязан загрузить все снимки до первого вопроса —
 * во время раунда сети быть не должно (`AGENTS.md`), — и гадать об адресе ему
 * нельзя, иначе он прогреет не то, что покажет.
 *
 * Ширины приходят из того же генератора, что и сами файлы: узкий оригинал не
 * растягивается до 1200, и такого файла у него просто нет.
 */
export function photoSource(photoId: string): string | null {
  const credit = PHOTO_CREDITS[photoId];

  return credit === undefined
    ? null
    : photoFile(photoId, Math.max(...credit.widths));
}

/**
 * Весь `srcSet` строкой — чтобы разметка не собирала адреса сама.
 *
 * Разметке это знание ни к чему, а стоило дорого: адрес файла был записан
 * дважды, здесь и в `CollectionImage`, и базовый путь сайта пришлось бы
 * заводить в оба места.
 */
export function photoSourceSet(photoId: string): string | null {
  const credit = PHOTO_CREDITS[photoId];

  return credit === undefined
    ? null
    : credit.widths
        .map((width) => `${photoFile(photoId, width)} ${width}w`)
        .join(', ');
}
```

### Задача 3: выкладка работой в `checks.yml`

**Файлы:**
- Изменить: `.github/workflows/checks.yml`

**Связи:**
- Берёт: каталог `dist`, который оставляет шаг `npm run build` (задача 2).
- Отдаёт: обновление сайта при каждом слиянии в `master`.

Проверить этот файл прогоном нельзя, не отправив его в GitHub, поэтому вместо
теста здесь — разбор синтаксиса и проверка после слияния (задача 4).

- [ ] **Шаг 1: переписать шапку файла**

Заменить весь комментарий в начале файла и строку `name:` на:

```yaml
# Проверки готовности изменения (AGENTS.md, «Готовность изменения») и выкладка
# сайта.
#
# Один прогон, четыре шага в том же порядке, в каком их гоняют руками. Порядок
# не случаен: линтер и тесты быстрые и ловят большинство, а `npm run build`
# идёт последним, потому что он самый долгий — и самый дотошный. Внутри него
# три валидатора контента и карты стоят до компиляции, поэтому несогласованные
# данные роняют прогон раньше, чем ошибки типов.
#
# Ручной прогон уже дважды поймал то, чего не видят тесты: ошибку типа в
# каталоге, объявленном `as const`, и китайский знак вне подмножества шрифта.
# Здесь это перестаёт зависеть от того, вспомнят ли о проверке.
#
# Выкладка стоит здесь же, а не отдельным файлом, ради одного свойства: на
# сайт уходит ровно тот `dist`, который прошёл проверки. Отдельный файл собирал
# бы заново, и однажды собрал бы не то.

name: Проверки и выкладка
```

- [ ] **Шаг 2: снять отмену прогона на `master`**

Заменить блок `concurrency` (он на уровне файла, сразу после `on:`) на:

```yaml
# Новый пуш в ту же ветку отменяет предыдущий прогон: зелёным должен быть
# последний коммит, а не каждый промежуточный. На master отмены нет: очередь
# на уровне файла обрывает весь прогон целиком, вместе с выкладкой, а сайт
# нельзя оставлять заменённым наполовину.
concurrency:
  group: checks-${{ github.ref }}
  cancel-in-progress: ${{ github.ref != 'refs/heads/master' }}
```

- [ ] **Шаг 3: отдать сборку артефактом**

После шага `- run: npm run build` (он последний в работе `checks`) добавить:

```yaml

      # Собранный сайт уходит артефактом, а работа выкладки его забирает. Так
      # на сайт попадает ровно то, что прошло проверки: пересборка в другой
      # работе однажды дала бы другой результат. Только на master — на ветках
      # артефакт никому не нужен, а весит он 16 МБ.
      - if: github.ref == 'refs/heads/master'
        uses: actions/upload-pages-artifact@fc324d3547104276b827a68afc52ff2a11cc49c9 # v5.0.0
        with:
          path: dist
```

- [ ] **Шаг 4: добавить работу выкладки**

В конец файла, на один уровень с `checks:` (два пробела отступа), добавить:

```yaml

  deploy:
    name: Выкладка на GitHub Pages
    needs: checks
    if: github.ref == 'refs/heads/master'
    runs-on: ubuntu-latest

    # Права выдаются работе, а не файлу: публиковать разрешено только ей, а
    # проверки остаются с одним чтением. `id-token: write` нужен доверенной
    # выдаче токена, которой Pages убеждается, что артефакт пришёл из этого
    # прогона, а не подложен со стороны.
    permissions:
      pages: write
      id-token: write

    # Своя очередь, общая для всех веток: две выкладки разом заменяли бы
    # содержимое сайта наперегонки. Начатую не обрываем — в отличие от
    # проверок, обрыв на полпути оставит сайт в неизвестном состоянии.
    concurrency:
      group: pages
      cancel-in-progress: false

    # Окружение `github-pages` заводит GitHub сам, когда источником выбран
    # GitHub Actions. Адрес сайта попадёт в сводку прогона.
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}

    steps:
      - id: deployment
        uses: actions/deploy-pages@368f82528645a54fb793d4d04e342629a3f51346 # v5.0.1
```
