# Города на карте: каталог, обобщённая цель и три игры

## Цель

Добавить второй набор учебных целей — города — и три игры по ним: «Найти
город», «Назвать город», «Город — регион». Попутно обобщить цель в движке
раунда так, чтобы физическая география (реки, хребты, пустыни) позже
добавлялась тем же способом и без второй миграции прогресса.

Границы: смешанные раунды «регионы + города», заполнение карты городами,
численность населения и экономика городов, города за пределами КНР — вне
этого изменения.

## Предусловие

Панорамирование карты при увеличении. Сейчас зум — масштабирование внутри
контейнера с обрезкой (`ROADMAP.md`), поэтому краевые области уходят за край.
Города это обостряют: самая плотная их часть — восточное побережье, то есть
край карты. Режим не выпускается, пока панорамирования нет.

## 1. Каталог городов

Новый `src/content/cities.ts` рядом с `regions.ts`:

```ts
export type CityKind = 'capital' | 'notable';

export type City = {
  readonly id: string;         // chengdu
  readonly regionId: string;   // sichuan
  readonly kind: CityKind;
  readonly nameRu: string;
  readonly nameZh: string;
  readonly pinyin: string;
  readonly lon: number;        // градусы, не единицы viewBox
  readonly lat: number;
  readonly sourceIds: readonly string[];
};
```

Координаты хранятся в градусах, проекция применяется при сборке слоя. Если
карта когда-нибудь заменится, города переедут пересчётом, а не станут молча
неверными — как уже случилось с прежним контуром Тайваня.

Состав: 31 столица провинциального уровня плюс около двадцати городов,
которые всё равно всплывают на уроке (Шэньчжэнь, Сучжоу, Циндао, Далянь,
Сямынь, Лоян, Кайфэн, Кашгар и подобные). Точный список утверждает
преподаватель.

### Столица перестаёт быть полем региона

`Region.capitalRu` и `Region.capitalZh` заменяются на
`Region.capitalCityId: string`, а игра «Регион — столица» берёт имя из
каталога городов. Иначе у Чэнду появляется два места правды, и они разъедутся.

### Что набирается руками

Natural Earth даёт координаты и латиницу, но не даёт русских имён,
иероглифики и пиньиня с тонами. У 31 столицы русское и китайское имя уже
проверены в `regions.ts`, не хватает пиньиня столицы (там только пиньинь
региона) и координат. У значимых городов нужно всё целиком. Источник
фиксируется в `docs/sources` по образцу `map.md`.

### Муниципалитеты

Пекин, Тяньцзинь, Шанхай и Чунцин существуют и как регион, и как город: две
цели в одной точке. Для «Найти город» это нормально, «Город — регион» для них
тавтологична. Правило: город, чей регион имеет `kind === 'municipality'`, в
третью игру не попадает. Свойство выводится из каталога, а не ставится
флагом, — флаг забудут проставить.

## 2. Обобщённая цель в движке

```ts
export type TargetKind = 'region' | 'city';
export type Target = { readonly kind: TargetKind; readonly id: string };
```

`Question.regionId` и `Attempt.regionId` заменяются на `target: Target`. Это
всё изменение модели.

**Производное остаётся производным.** `masteredRegionIds` и
`regionIdsToRepeat` в `progress-rules.ts` считаются из массива попыток, а не
хранятся отдельно. Значит «какие города повторять» и «какие города освоены» —
те же функции с фильтром по `target.kind`. Они переименовываются в
`masteredTargets` и `targetsToRepeat` и получают вид цели параметром.
Раздельность нужна именно здесь: «путает Ланьчжоу с Синином» не должно
смешиваться с «не знает Ганьсу».

**Уровней не существует.** Лестница снята решением от 2026-08-05,
`unlockedLevel` из `Progress` удалён, игры равноправны и открыты все сразу.
`Level` остаётся внутренним свойством игры — какими представлениями она
спрашивает — и наружу не показывается. `unlockedLevelFrom` в этом изменении
не участвует.

Попутная возможность: то же решение отложило переименование типа `Level`,
потому что оно задело бы домен, хранилище и полтора десятка тестов, ничего не
изменив в поведении. Шаг 1 трогает ровно эти файлы по другой причине, поэтому
переименование стоит доделать в нём же, а не платить за тот же обход дважды.

**Представления общие.** `representationsFor` берёт из `Region` только три
имени — русское, иероглифическое и пиньинь. У города они те же, поэтому
функция начинает принимать структуру с тремя именами, а не конкретный тип.

**Типы упражнений описывают форму вопроса, а не цель.** Три формы одинаковы
для регионов и городов: найти по имени, назвать по месту, связать с другим
каталогом. Поэтому `name-region` → `name-target`, `match-capital` →
`match-pair`; `find-on-map` остаётся. Значения хранятся в попытках, так что
переименование всё равно идёт миграцией: сейчас оно почти бесплатно, позже
потребует второй.

### Миграция прогресса v1 → v2

Механическая, угадывать нечего:

```
{ regionId: 'sichuan', exerciseType: 'name-region' }
→ { target: { kind: 'region', id: 'sichuan' }, exerciseType: 'name-target' }
```

`masteredRegionIds: ['sichuan']` → `masteredTargets: [{ kind: 'region', id:
'sichuan' }]`.

`progress-storage.ts` уже откладывает непонятые данные в `BACKUP_KEY` вместо
удаления, чем выполняет требование `DATA_MODEL.md`. Добавляется только функция
перевода и тест на ней.

## 3. Слой городов на карте

**Слой строится скриптом.** `scripts/generate-city-points.ts` по образцу
`generate-taiwan-path.ts` берёт градусы из каталога, прогоняет через
`projectLonLat` и пишет сгенерированный `src/map/city-points.ts` с
координатами в единицах viewBox. Файл карты не трогается: контракт
`MAP_SPEC.md` на 34 области сохраняется.

**Рендер поверх.** Карта подставляется через `dangerouslySetInnerHTML`,
поэтому города — отдельный `<g>`, который React рисует над ней в том же
viewBox. Тот же приём, что уже применён для `<defs>` в `MapDefs.tsx`.

### Одна точка — три сущности

1. **Знак** — кружок около 2.5 единиц, декоративный (`aria-hidden`), всегда
   на настоящем месте.
2. **Цель нажатия** — невидимая, не меньше `MIN_TARGET_PX` = 24 px, и может
   быть смещена относительно знака.
3. **Подпись** — только при наведении, фокусе и выборе.

Разделение решает плотность. При опорной ширине 1120 px 24 px — это около 17
единиц viewBox, а между Шанхаем и Сучжоу примерно 4 единицы, то есть 5 px:
цели неизбежно наложатся. `generate-hit-targets.ts` получает этап разведения
целей, знаки остаются географически честными. Это ровно то, что уже сделано
для Гонконга и Макао, где контур декоративен, а маркер вынесен в акваторию.

**Где геометрия не спасает.** Гуанчжоу, Шэньчжэнь, Гонконг и Макао на 320 px
не разведёт ничто. Работают два существующих ответа: из близкой пары в набор
берётся один город, а на узком экране игра предлагает равнозначный список
вместо карты — `region-answer-list` готов и просто получает города.

**Подписи без раскладки.** Подпись видна у одной точки за раз, поэтому задача
взаимного расположения пятидесяти надписей не возникает. Единственная забота —
не уйти за край viewBox: сторона выбирается по положению точки. Полный список
городов региона живёт в его карточке рядом с фактами.

**Состояния — не цветом.** Цветовой канал занят тремя раскладками (тип
региона, исход ответа, освоенность), и `tokens.css` фиксирует, что окно
светлоты уже узкое. У знака свои каналы: размер, обводка и форма. Ошибка
помечается формой знака по тому же правилу, по которому у областей она
помечена штриховкой.

**Когда слой виден.** В атласе, в карточке региона, на странице коллекции и в
играх по городам. В играх по регионам он скрыт: там точка в центре Сычуани —
подсказка, а не цель.

## 4. Игры и экраны

Города дают три равноправные карточки в общем ряду `MODE_CARDS`, рядом с
четырьмя существующими. Лестницы нет, все открыты сразу.

| Карточка | Что спрашивает | Объём |
| --- | --- | --- |
| Найти город | имя → нажатие по точке | около 50 городов · около 10 минут |
| Назвать город | подсвеченная точка → четыре имени | около 50 городов · около 9 минут |
| Город — регион | имя города → нажатие по области | на 4 города меньше · около 9 минут |

Третья короче ровно на четыре города-муниципалитета. Точные числа следуют из
каталога и в карточках не пишутся руками — иначе они разойдутся с ним, как
это уже учтено у коллекций с числом фотографий.

**Отвлекающие в «Назвать город» должны быть географически близкими.** Если к
подсвеченной точке в дельте Янцзы предложить Урумчи, Куньмин и Харбин, вопрос
решается по грубому положению и не проверяет ничего. Правило: тот же
`CityKind` и по возможности соседние регионы. У регионов такой заботы нет, там
отвлекающие берутся по типу единицы.

**«Город — регион» не нуждается в отвлекающих**: карта сама и есть выбор из
тридцати четырёх.

**Язык вопроса выбирается так же, как у регионов.** Каждая городская карточка
получает переключатель «Русское / 中文»; пиньинь у города остаётся в каталоге
для показа, но вопрос его не задаёт. Освоенность города подчиняется общему
правилу: три верных ответа в разных раундах, хотя бы один — на вопрос
иероглифами.

**Иероглиф-метка.** Заняты 地 名 都 填 史 文. Для городов напрашиваются 市,
认, 属, но выбор сверяется с преподавателем. Новые знаки требуют
`npm run generate:fonts`, иначе сборка падает.

**Атлас принимает города в поиск.** Запрос «Сучжоу» приводит на карточку
Цзянсу с подсвеченной точкой. `region-search` расширяется до поиска по обоим
каталогам: иначе город можно потренировать, но нельзя посмотреть.

## 5. Проверки

Валидаторы, падающие на сборке до компиляции:

- `validate:content` — уникальность `id` городов, существование `regionId` и
  `sourceIds`, непустые имена во всех трёх представлениях, у каждого региона
  ровно один город с `kind: 'capital'`, совпадающий с `capitalCityId`.
- `validate:map` — новый этап: каждая точка внутри контура своего региона;
  каждая цель нажатия не меньше 24 px при опорной ширине; цели не
  перекрываются. Точка в многоугольнике считается по кольцам, которые
  `svg-path.ts` уже разбирает для `largestInscribedCircle`. Эта проверка
  ловит три разные ошибки сразу: опечатку в координатах, неверную привязку к
  региону и расхождение проекции.
- `validate:fonts` — сработает сам; про него надо помнить заранее, новые
  города приносят незнакомые иероглифы.

Тесты:

- миграция v1 → v2: прогресс, записанный до неё, после даёт тот же список
  освоенного;
- раунд по городам: каждый город ровно один раз, порядок воспроизводим по
  сиду;
- отвлекающие в «Назвать город» — того же вида и не с другого конца страны;
- муниципалитет не попадает в «Город — регион»;
- освоенность и список на повторение не смешивают регионы с городами;
- на 320 px игра показывает равнозначный список.

Ручная проверка: мышь, касание, Tab, Enter, Space, Escape, 320 px.

## 6. Порядок работ

Четыре шага, каждый проверяем отдельно:

1. **Обобщение цели и миграция прогресса.** Поведение не меняется вообще;
   критерий готовности — все существующие тесты проходят без правок ожиданий.
   Сливается отдельным изменением: шаг трогает домен и хранилище, и мешать его
   с новым контентом в одном ревью не надо.
2. **Каталог городов, валидаторы, генератор точек.** Экранов ещё нет;
   готовность — валидаторы проходят, точки совпадают с картой.
3. **Слой городов и цели нажатия.** Виден в атласе и карточке региона; игр
   ещё нет.
4. **Три игры, карточки на главной, поиск городов в атласе.**

## Готовность

Ученик может найти город на карте, назвать подсвеченный город и определить его
регион; ошибки по городам попадают в повторение отдельно от ошибок по
регионам; каждый город имеет проверенный источник, а его точка подтверждена
геометрической проверкой. Физическая география в этот объём не входит, но
добавляется как третий `TargetKind` без миграции.
