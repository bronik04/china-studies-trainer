## Команды

```bash
npm run dev                      # Vite, разработка
npm test                         # vitest run — весь набор
npx vitest run src/domain/round.test.ts        # один файл
npx vitest run -t 'название теста'             # один тест по имени
npx vitest                       # режим наблюдения
npm run lint                     # eslint .
npm run build                    # три валидатора → tsc -b → vite build
```

`npm run build` — это и есть полная проверка контента: `validate:map`, `validate:content` и `validate:fonts` идут **до** компиляции, и сборка падает на несогласованных данных раньше, чем на типах. Валидаторы можно гонять по одному (`npm run validate:map`).

## Генераторы: часть файлов нельзя править руками

| Команда | Что делает |
| --- | --- |
| `npm run generate:palette` | перезаписывает `src/map/region-palette.ts` целиком по геометрии SVG |
| `npm run generate:callouts` | правит `public/maps/china-provinces.svg` на месте — выноски для Макао и Гонконга |
| `npm run generate:hit-targets` | правит тот же SVG — невидимые цели нажатия для регионов мельче порога WCAG |
| `npm run generate:fonts` | пересобирает подмножества шрифтов в `src/assets/fonts` и `scripts/font-coverage.json` |

Оба SVG-генератора идемпотентны, их блоки ограничены комментариями-метками. Перед правкой любого файла в `src/map/` или самого SVG прочитайте шапку файла: сгенерированные помечены явно.

**Новый иероглиф в контенте ломает сборку.** Шрифты подмножествованы; `validate:fonts` сравнивает знаки, встречающиеся в `src`, с покрытием подмножеств. Добавили регион с незнакомым иероглифом — запустите `npm run generate:fonts`, иначе сборка падает (это лучше, чем квадратик в браузере).

## Архитектура

**Роутера нет.** `src/App.tsx` — конечный автомат экранов (`Screen`) и единственное место навигации: он держит весь прогресс, состояние раунда и решает, показывать ли шапку. Новый экран добавляется здесь, а не отдельным маршрутом.

- Шапка (`SiteHeader`) закреплена и стоит на всех поверхностях — её рисует `AppFrame`, а не каждый экран. Высоту кадра под ней считает `.app-frame`, поэтому оболочки внутри о шапке ничего не знают. Карта раунда из-за неё меньше на 69 px: 804×600 вместо 897×669 при кадре 1440×900.
- `AppFrame fillsFrame` — поверхность занимает экран и не прокручивается. Признак ставится у каждого возврата отдельно, намеренно, а не списком экранов.

**Слои и их границы:**

| Каталог | Правило |
| --- | --- |
| `src/content` | справочники регионов, коллекций и источников; чистые TS-модули, валидируются на сборке |
| `src/domain` | чистые функции: раунды, оценивание, прогресс. Не знает ни React, ни DOM |
| `src/features` | поверхности: `home`, `atlas`, `collections`, `exercise`, `results` |
| `src/map` | SVG, фокус, масштаб, сопоставление областей с `regionId` |
| `src/ui` | общая обвязка сайта |
| `src/design` | разбор токенов и пороги контраста (чистый код; чтение с диска — в `scripts/`) |

Границы, которые легко нарушить незаметно:

- **Домен не вызывает `Math.random`.** Генератор передаётся снаружи (`createSeededRandom`, mulberry32) — иначе раунды перестают воспроизводиться в тестах. Сид создаётся в `App.tsx`.
- **Компоненты не трогают localStorage.** Только через `createProgressStore` (`src/domain/progress-storage.ts`).
- **UI не знает ключей SVG, карта не считает правильность ответа.**

**Прогресс вычисляется, а не читается.** `masteredRegionIds` и `unlockedLevel` сохраняются в хранилище (этого требует `DATA_MODEL.md`), но на каждом `commitAttempts` пересчитываются заново из истории попыток — отставшее поле не должно запереть ученика.

**Хранилище деградирует, а не падает.** Доступ обёрнут в try (политика браузера может запретить `localStorage`), запись проверяется пробной записью, а испорченные данные не удаляются — они переносятся в `BACKUP_KEY`, чтобы неудачная миграция ничего не уничтожила. Флаг `store.isAvailable` доходит до экранов итогов: ученика предупреждают, что прогресс не сохранится.

**Карта.** `public/maps/china-provinces.svg` — единственный источник геометрии, попадает в бандл через `import ... from '...svg?raw'`, то есть на сборке, а не запросом. Размер цели нажатия меряется диаметром наибольшей вписанной окружности, а не габаритом контура: у Ганьсу габарит огромный, а сама область — узкий коридор.

**Токены.** `src/design/tokens.css` — единственный источник цветов, размеров и длительностей; компоненты не пишут значения напрямую. `scripts/validate-tokens.test.ts` разбирает тот же файл и проверяет по WCAG 2.2 каждую пару, реально встречающуюся на экране, — палитру нельзя ухудшить незаметно, тест упадёт.

## Что помнить при изменениях

- Интерфейс, задания и ошибки — по-русски; китайские названия в Unicode, не только пиньинем.
- Во время раунда сетевых запросов нет: приложение работает после первоначальной загрузки.
- Существенное решение фиксируется в `DECISIONS.md`, изменение — в `CHANGELOG.md`.
