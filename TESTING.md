# Тестирование

Документ описывает то, что есть. Задуманное, но не сделанное, помечено
явно — иначе список проверок обещает больше, чем защищает, и на него нельзя
опереться при выпуске.

## Автоматические проверки

Три команды, и `npm run build` — самая дотошная из них.

| Команда | Что делает |
| --- | --- |
| `npm run lint` | ESLint по всему репозиторию |
| `npm test` | весь набор Vitest; счёт файлов и тестов печатает сама команда |
| `npm run build` | `validate:map` → `validate:content` → `validate:fonts` → `tsc -b` → `vite build` |

Валидаторы стоят до компиляции намеренно: несогласованные данные роняют сборку
раньше, чем ошибки типов, и сообщение говорит о карте или контенте, а не о
типе.

- **`validate:map`** — геометрия: 34 области и ровно один контур на регион,
  цели нажатия и выноски, размер целей по WCAG 2.5.8, линии рек внутри рамки,
  каждый заявленный регион действительно задет, отрезок не отдан двум рекам.
  Плюс отпечатки входов у всех сгенерированных файлов карты: забытый генератор
  роняет сборку и называет команду.
- **`validate:content`** — справочники: уникальные идентификаторы, непустые
  имена в трёх формах, существующие регионы и источники, 2–3 факта с
  источником у региона и у цели физической географии, у коллекции — вводка и
  3–4 заметки, если её содержание написано руками.
- **`validate:fonts`** — знаки: шрифты подмножествованы, и знак, встретившийся
  в `src` и не покрытый подмножеством, роняет сборку. Лучше падение, чем
  квадратик в браузере.

Где живёт покрытие:

| Область | Что проверяется |
| --- | --- |
| `src/map` | геометрия, попадания, вид, слои |
| `src/domain` | раунды, оценивание, прогресс, хранилище |
| `src/features/exercise` | режимы и ход раунда |
| `src/content` | каталоги и их согласованность |
| поверхности | главная, коллекции, атлас, итоги |
| `src/App.test.tsx` | переходы между экранами и общая обвязка |
| `scripts` | генераторы, отпечатки входов, палитра токенов |

Чисел здесь намеренно нет. Они устаревают с первым же коммитом — документ
дважды обещал 619 тестов, когда их было уже под тысячу, — а сказать, сколько
их сейчас, умеет сама команда.

Отдельно стоит `scripts/validate-tokens.test.ts`: он разбирает
`src/design/tokens.css` и проверяет по WCAG 2.2 каждую пару цветов, реально
встречающуюся на экране. Палитру нельзя ухудшить незаметно.

**Прогон на пуш.** `.github/workflows/checks.yml` гоняет `npm ci`,
`npm run lint`, `npm test` и `npm run build` на любую ветку и сверяет базовый
путь собранного сайта с именем репозитория. На master тот же прогон после
зелёных проверок выкладывает проверенный `dist` на GitHub Pages.

### Чего в автоматических проверках нет

- **Тестов доступности как отдельного слоя.** Инструмента вроде `axe` в
  зависимостях нет. Доступность держится на другом: тесты поверхностей ищут
  элементы по ролям и доступным именам, поэтому потерянная роль или имя роняет
  тест; контраст проверяет `validate-tokens.test.ts`; размер целей нажатия —
  `validate:map`. Фокус, порядок обхода и работа читалки экрана проверяются
  руками.
- **E2E.** Playwright или Cypress в зависимости не заведены. Сквозной путь —
  пройти раунд, завершить, повторить ошибки, перезагрузить и увидеть
  прогресс — покрыт в `src/App.test.tsx` на jsdom: это не настоящий браузер,
  и раскладку, прокрутку и жесты он не проверяет.

Обе строки задуманы, но не сделаны. Пока их нет, ручная проверка ниже —
не формальность, а единственное место, где это проверяется.

## Ручная проверка

Основной сценарий проверяется перед каждым слиянием (`AGENTS.md`, «Готовность
изменения»).

- **Мышью.** Карта нажимается, увеличивается, показывает фокус и наведение; на
  физической карте объект под курсором подсвечивается тот же, который выберет
  нажатие.
- **Только с клавиатуры.** Дойти до режима, ответить на карте, прочесть
  результат, закончить раунд, вернуться в раздел.
- **Без сети после загрузки.** Отключить сеть и пройти раунд целиком, зайти в
  атлас и включить физическую карту. Экраны разделены на куски сборки, и это
  проверка того, что дотягивание кусков в простое действительно случилось
  (решение от 2026-08-27).
- **Узкий экран не проверяется.** Мобильный режим снят с плана решением
  владельца от 2026-08-27; прежний пункт про 320 px убран, чтобы список не
  обещал того, чего не делают.

## Контентная проверка

Для каждого региона сопоставить SVG-область, русское и китайское названия,
пиньинь, административный центр и источники. Для каждой цели физической
географии — имя, род, регионы и справку. Второй проверяющий читает карточки на
фактические и языковые ошибки. Спорный контент не должен утверждаться как
бесспорный факт.

## Регрессия

Перед выпуском повторить все сценарии из `ACCEPTANCE_CRITERIA.md`. Любой
дефект, приводящий к неверному учебному ответу, блокирует выпуск.
