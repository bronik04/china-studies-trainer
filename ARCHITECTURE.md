# Архитектура

## Подход

Клиентское одностраничное приложение. Доменная логика не зависит от React/представления: генерация раундов, оценивание ответа, выбор повторений и расчёт прогресса — чистые функции с тестами. Карта — отдельный адаптер, который связывает SVG-идентификатор с `regionId`.

## Слои

| Слой | Ответственность |
| --- | --- |
| `content` | версии справочников регионов, упражнений и источников |
| `domain` | правила раунда, оценивание, прогресс |
| `storage` | локальное чтение, миграции и безопасная деградация |
| `features` | поверхности приложения: кабинет (`home`), атлас (`atlas`), раунд (`exercise`), итоги (`results`) |
| `ui` | компоненты, стили, доступность |
| `map` | SVG, фокус, масштабирование, сопоставление областей |

## Данные и границы

Приложение живёт тремя поверхностями. Кабинет отвечает «где я и что дальше»:
карта освоенности и единственный главный шаг. Атлас — «рассмотреть и найти»:
карта во весь кадр и справочник в панели. Раунд — «ответить». Постоянной
навигации нет, кабинет служит хабом: раунд занимает ровно кадр, и полоса
навигации отняла бы высоту у карты.

Контент приходит из локальных JSON/TS-модулей, валидируется при сборке. UI не знает о ключах SVG, а карта не вычисляет правильность ответа. Никакой компонент не изменяет локальное хранилище напрямую: доступ идёт через `ProgressRepository`.

## Расширение

Новые темы добавляются как пакеты контента с единым интерфейсом `Topic`. Серверная синхронизация, если появится, реализуется вторым адаптером репозитория; текущий API домена не должен от неё зависеть.

## Производительность

SVG загружается один раз и не перерисовывается целиком после ответа. Справочник и история прогресса небольшие; хранить агрегаты и последние попытки, а не неограниченный журнал событий.
